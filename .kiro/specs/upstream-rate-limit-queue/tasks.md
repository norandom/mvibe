## Implementation Notes
- 1.3/1.4 review: gate tests use `_bounded` (5 s `asyncio.wait_for`) so regressions fail instead of hanging; keep wrapping any new multi-run gate test. A fake `attempt` that never suspends can still spin synchronously under a hold-skipping regression; add `await asyncio.sleep(0)` in scripted attempts.
- 1.4 review (optional follow-ups, owner noted): apply the hold before reading the 429 body so a cancel during the read still holds the key (gate, 2.4 may adopt); validate `backoff_cap_s > 0` in `UpstreamGate.__init__` or close the response when `classify` raises (gate); `GateRecord.headers` merges across rejections while its docstring says "latest snapshot" (settle in 2.2 when moving `GateRecord` to diagnostics).
- `UpstreamGate(..., wall_clock=time.time)` exists for HTTP-date Retry-After; `clock` stays monotonic. `gate_factory` in 2.3 should pass only `config` and let defaults apply.
- 2.1 review (non-blocking, for 2.4): in `_OwnedResponse.__call__` the `AuthError`/generic handlers call `failure('auth')`/`failure('connection')` without the `not disconnected` guard that `upstream()` has; if the gate ever defers a cancellation and then raises, guard both so the outcome stays `cancelled`.
- 2.1 review (non-blocking, for 2.5): if `receive()` itself raises inside the `acquire_watching` watcher, the caller sees a `BaseExceptionGroup`, not an unwrapped error; `adapter_post` should treat that as a connection failure.
- Route handlers read the body through `proxy._read_body(request, diagnostic)`; `None` means the client disconnected (diagnostic `cancelled`, return `Response(status_code=204)`). New routes must use it before acquiring.
- 2.2: `GateRecord` lives in `mvibe_proxy/diagnostics.py` (re-exported by `ratelimit`); the exhausted-429 stdout test attaches the record via a `RequestDiagnostic` subclass until 2.4 wires the gate. `tests/test_observability.py` now skips only the two OpenTelemetry-SDK tests, not the whole module.
- 2.3: default `gate_factory` is `proxy._default_gate` (supplies the `proxy_rate_limit_hold` warn logger); tests inject their own factory. For 2.4: sanitize the gate key (client-supplied model string) before it reaches the warn log line (`repr` or strip control characters); add `MVIBE_RATE_LIMIT_` to `tests/conftest.py::isolate_environment` so a developer's shell cannot make `main()` tests exit 2.
- 2.4: every `make_acquire` request runs through the gate; `key_for(path, model)` (printable, 128-char cap) keys pacing; `UpstreamGate.now()` supplies `arrived`; attribution and econ run once in `prepare(snapshot)` on the first attempt. Tests use `clocked_gate`/`answers`/`SHORT_WAIT` with a 50 ms simulated upstream latency because a zero-latency 429 whose Retry-After is clamped to `max_wait_s` re-sends once exactly at the deadline (gate edge, task 2.6). The gate builds exhausted 429s with `x-ratelimit-*` before `retry-after`; header order is not a contract. Every `proxy_request` row now carries `queued_ms` and `rate_limit_rejections`.
- 2.5: adapter routes acquire through `acquire_watching`; a disconnect during or behind a hold yields `cancelled` and an empty 204; a failing `receive()` surfaces as an `ExceptionGroup` and is answered 502 (401 when every member is `AuthError`); only 429 translated errors carry `retry-after`/`x-ratelimit-*`.
- 2.6: exhaustion is decided on the unclamped wait (strict `>`); the key's hold is always set (clamped) and `warn` fires once even when the observing run gives up; gate `clock` defaults to `time.perf_counter`; gate 429s carry raw-byte headers (non-ASCII round-trips); warn line renders the key with `%r`. Tests no longer simulate upstream latency; `SHORT_WAIT` is `max_wait_s=0.5` because a 1 s backoff against a 1 s wait ends exactly on the deadline and legitimately re-sends.
- 3.1: `src/rate-limit.ts` mirrors the Python classification (status-only 429, uncapped Retry-After, `min(fallback, cap)` otherwise, `x-ratelimit-*` snapshot ≤64 chars); `classifyRateLimit` throws `RangeError` for a non-positive fallback/cap before the status check (Infinity accepted); HTTP-dates use a strict grammar (not `Date.parse`) and fall back more readily than Python; `parseRateLimitOptions` names model entries by position when the name is unsafe; `MODELS_KEY` is module-private (3.2 may export it). In `bun:test`, array-valued `test.each` cases are spread into arguments: wrap them in one-element tuples.
- 3.2: TS `UpstreamGate` core mirrors the Python gate (FIFO per key, cross-key `maxQueue`, strict head deadline, slot-past-deadline refusal, pruning guard, abort at entry before the queue check, listeners removed on every exit); default sleep is a real timer cleared on abort; fake sleep in tests yields a macrotask so the 5 s `bounded` timeout can fire. For 3.3: `record.queuedMs` must be accumulated per wait segment (reset after each 429) to avoid double counting; flip the "returns an upstream 429 unchanged" test; optional tests for `clearTimeout` on abort, a sleep rejecting with `AbortError` mapping to `cancelled`.
- 3.3: TS gate 429 handling mirrors the proxy; on exhaustion the SAME `Response` is returned unread and unaltered (no `retry-after` added; Req 4.3); the body of a retried 429 is cancelled without awaiting; the give-up check is `max(rejectedAt + wait, readyAt()) > deadline`; `GateDeps.wallNow` (default `Date.now`) feeds HTTP-date parsing; `queuedMs` is counted per wait segment.
