## Implementation Notes
- 1.2/1.3 (controller, direct): `RequestDiagnostic.usage: tuple[int, int] | None` → `usage_prompt_tokens`/`usage_completion_tokens` on stdout and export (allowlisted); `diagnostics.set_counters_sink(callable | None)` is called once per `emit()` after the channels, inside its own never-raise guard. `StdioMcpClient.call_tool(name, arguments, *, timeout_ms)` returns the raw `result`; `shunt_content` delegates to it (timeouts name the tool, never the arguments).
- 4 (controller, direct): `./mmhmem-data:/data/mmhmem` bind mount, `AGENT_MEM_DATA_DIR`/`AGENT_MEM_LOG_FILE`, `MVIBE_STATS_USAGE: "1"` and `MVIBE_STATS_MMHMEM_BIN` are active in docker-compose.yml (econ keys stay commented); `mmhmem-data/.gitkeep` tracked with `mmhmem-data/*` + `!mmhmem-data/.gitkeep` ignore rules; `test_compose_persists_mmhmem_state_next_to_the_compose_file` guards it. Verified `docker compose config` through the Podman provider renders the mount as `D:\Source\mvibe\mmhmem-data -> /data/mmhmem`. The compose default sets the stats keys before the proxy reads them (task 3.1); until then they are ignored. Ownership of the bind mount for uid 1000 inside the Podman machine is a live-check item.
- 1.1: `ProxyStreamOwner.response(..., observe_factory=None)`; the factory runs once after acquisition (not when the client already left or on a 401/502 path); `_stream_body` feeds raw upstream chunks before any transform and sends the terminal `None` once the body was read to the end (even if the bounded close then fails); interrupted or cancelled streams never report completion; bodyless statuses get neither chunks nor `None`. Routes do not pass a factory yet (3.2). Test helper `call(..., path=)` and `tapped(app, factory)` exist in tests/test_streaming.py.
- 2.1–2.3 (one dispatch): `mvibe_proxy/stats.py` with `StatsConfig` (off values `0/false/no/off`; any other non-blank value is an error; binary messages omit the path; `from_env` raises on an invalid binary even when usage is off — `main()` downgrades that to a warning unless `--stats`/`MVIBE_STATS_USAGE` is set), `UsageObserver` (SSE keeps the last usage; a partial line beyond 4 MiB disables; malformed usage events are skipped), `UsageLedger` (+ `requests_by_model()`), `ProxyCounters` with `report_succeeded(at)`/`report_failed()` as the only report writers (2.4 must call them). An AST test pins that `stats` imports only `diagnostics` and stdlib.
- 3.2 (controller, direct): `proxy.usage_factory(diagnostic, target)` returns `None` for model-list targets and otherwise an `observe_factory` building `UsageObserver(content_type, model).as_callable(diagnostic)`; passed by the `/v1` route and by `adapter_post`'s replay. `diagnostic.model` was already set for embeddings by the rate-limit work. Tests read the emitted diagnostics row (`usage_prompt_tokens`/`usage_completion_tokens`) for raw chat (JSON and SSE), embeddings, `/api/chat` and `/v1/messages`; `/v1/models` and bodies without usage emit no usage fields. The `tapped()` helper in tests/test_streaming.py now accepts the routes' `observe_factory` keyword.
- 3.1+3.3 (controller, direct): `create_app(..., stats_config=None, stats_runner=_default_stats_runner, reporter_factory=_default_reporter)`; the defaults resolve `stats.UsageReporter` / `stats.mmhmem_stats` at call time so the wiring landed before task 2.4. Lifespan: `ProxyCounters` always built (`app.state.counters`) and registered as the diagnostics sink through a wrapper that skips requests flagged `diagnostic.local = True` (the `/health` and `/stats` handlers set it, so local routes never inflate `requests.total`); the stdio child starts when economics or `stats.usage` is on, from the econ binary when economics is on, else from the stats binary; economics owns it via the shunt (fail-fast unchanged), a stats-only child is `app.state.stats_child` and shut down by the lifespan after `reporter.stop()`; a stats-only child that fails to start logs one sanitized warning on `mvibe-proxy.stats` (class name only) and inference keeps serving (Req 2.4/4.3, decision: fail-fast stays econ-only). `main()`: `--stats` (exit 2 unless `usage` and a binary resolve), `StatsConfig.from_env()` errors exit 2 when `--stats` or `MVIBE_STATS_USAGE` holds an enabling value (an opt-out value such as `0` only warns), unwritable `AGENT_MEM_DATA_DIR` warning per design text, `Stats: http://<host>:<port>/stats` (IPv6 hosts bracketed) printed before serving. `GET /stats` is in OpenAPI with a response description; `tests/conftest.py` now also isolates `MVIBE_STATS_*`, `MVIBE_ECON_*`, `AGENT_MEM_*`. Follow-up once 2.4 lands: tests that the default runner reports `not_configured` for the inert config and that the default reporter factory builds a `UsageReporter`.
- 2.4: `UsageReporter(client: ToolCaller, ledger, *, project, interval_s, counters=None, task_id=None, clock, sleep, warn, timeout_ms)` with `start()`/`report()`/`stop()` (`FINAL_REPORT_TIMEOUT_S = 2.0`), one `session_resume_or_handoff` call per non-zero model source in sorted order with cumulative totals and one task id per process; a failure skips the remaining sources of that tick, counts once and warns once per streak naming the class only (default logger `mvibe.proxy`); a failed final report is counted too. `mmhmem_stats(bin_path, *, env, timeout_s, spawn=...)` runs `[bin, 'stats', '--json']` with stdin/stderr at DEVNULL (an unread stderr pipe could block the child), an 8 MiB stdout cap (`MMHMEM_STATS_STDOUT_LIMIT`; over the cap → `invalid_json` and the child is killed), kill + 1 s reap on timeout or cancellation, and the extra reason `spawn_failed` when the binary cannot be executed (added to the design enum).
